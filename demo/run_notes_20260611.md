## Hiccups found (chronological)
1. **ncclient INFO logging floods CLI output** — full hello/capability dumps in `setup`/`doctor`/`run` logs; ~95% noise. Should set ncclient loggers to WARNING.
2. **`setup_report.json` is stale** — written by `run`/smoke-test expansion phase, not by `setup`; root-level file still showed a March run of a different device. Confusing; should be per-device or refreshed.
3. **Catalog/jobs table never prunes** — catalog_paths for teraflex = 18,261 rows while today's build reported 13,281; upsert-only accumulation across firmware/config changes. Many accumulated paths fail at poll time (`task failed ... Not found node "..." in path`), wasting poller cycles on a device with strict session throughput.
4. **A job polls `/p1:bulk-data` whole-tree** — times out (10s, then retry, 22s wasted per round). Huge subtree should be excluded or auto-disabled after repeated timeouts.
5. **Telegraf 1.30 rejects `insecure = true`** in `inputs.gnmi` → all three telegraf containers crash-looped; **zero data reached InfluxDB**. Fixed: replaced with `enable_tls = false` in `demo/telegraf/*.conf`. (Option was removed/renamed in newer Telegraf; demo presumably last ran with an older image tag.)
6. **Grafana initially: 7 of 11 panels "No data"** — all Teraflex optical panels (Q-Factor, FEC BER, OSNR, Rx Power, CD, DGD, CFO) empty; only ROADM Power, ILA Amplifier, Temperature, Power Consumption had data (verified visually via Playwright screenshots).
7. **Root cause of missing optical PM: device re-provisioned since January.** Live interfaces are now `1/1/n1/ot500`, `1/1/n2/ot400`, `1/2/n1/ot400`, `1/2/n2/ot400` — `ot200` no longer exists. Config `pm_selector` still targeted `1/2/n2/ot200`; with `resolve_all_lists: false`, list_instances in DB were January-stale, so PM fanout generated filters for a ghost interface. Device politely returns empty data (no error!) for non-existent instance keys — silent failure mode.
8. **gNMI Get/Subscribe for `/pm/...` paths returns only what's in the TTL cache** — `LiveCache.match_prefix` falls back to DB only when the in-memory cache is *completely* empty. With sweep time >> TTL, PM values flicker in and out of gNMI responses. (teraflex `cache.ttl_sec: 600` mitigates; sweep is still slower than TTL.)
9. **PM sweep is slow due to session contention** — main poller (18k tasks, many failing) and PM poller (132→528 tasks) share one serialized NETCONF session; a PM round takes 10–20+ min, so `pm.interval_sec: 5` is aspirational.
10. **DB `psql` ergonomics**: `last_value` join needs `lv.canonical_path`/`value_json` (not `path`/`value`) — minor, but the column naming differs from cache-record keys (`path`/`value`), which is mildly confusing in code too.

11. **528 narrow PM filters ≈ hours per sweep** under session contention (~1 PM value/min observed). Residual string-typed fields remain in the current Influx shard; if panels stay numeric-less after the line is lit, purge the `gnmi` bucket.
13. **Synthetic PM path collision**: `/pm/{domain}/{name}/{mon_type}` omits the interface name, so all 4 fanned lines write the same paths (last writer wins). Needs an instance segment in the synthetic path for multi-line fanout to be meaningful.

# Round 3 (same day): productization sprint — 10 features

Implemented as product owner per Agastya's go-ahead; all design decisions validated
against the codebase by a 5-agent investigation workflow before coding, full diff
adversarially reviewed by a 2-phase review workflow after.

1. **Instance-keyed PM paths** (`pm.py`) — synthetic paths now carry their originating
   instance as gNMI keys discovered from reply-XML ancestors:
   `/pm/otnpm-data[interface=1%2F2%2Fn1%2Fot400,managed-element=1,otsi=1]/CarrierTF/acor-factt:opt-rcv-pwr`.
   Single bracket, comma-joined, alphabetically sorted, percent-encoded values — byte-identical
   to what `_path_to_str` canonicalizes incoming requests to, so client queries match exactly.
   Telegraf turns the keys into tags; Grafana field names unchanged. Verified against the
   live Teraflex (also discovered otsi sub-carrier keys — multi-carrier safe).
2. **Fat-filter collapse** (`_discover_pm_filters`) — roots under `pm_selector_list_path`
   collapse into ONE subtree filter per instance (4 filters replace ~470 narrow RPCs);
   roots outside it keep narrow per-root filters; unkeyed list-level filters are never
   emitted; selector zero-match degrades to the old narrow shape with a loud warning.
   Also fixed `_pick_pm_fanout_list_path` honoring the preferred list for roots NOT under it.
3. **Drift detection** — `run` re-resolves the fanout list at startup and rebuilds PM
   filters when instances changed (`discovery.pm_refresh_on_run`, default true, conservative
   on failure); new `doctor` check `pm_filters` fails on ghost instances / zero-match
   selectors (verified live: PASS on current teraflex).
4. **Poller failure breaker + stats** — per-task consecutive-failure auto-disable
   (`poller.task_failure_limit`, default 5) with circuit-breaker sweep rollback (an outage
   can't disable healthy paths); sweep stats exposed via `/health`.
5. **`status` command** — health + per-interval sweep stats + disabled tasks; DB-freshness
   fallback when no bridge is running. Handles 503-with-JSON-body.
6. **`build-catalog/setup --prune`** — deletes catalog/aliases/jobs/list_instances absent
   from the current build; keyed jobs survive via predicate-stripped matching; /pm and
   onboarded jobs untouched; refuses when new < 50% of stored (--force overrides).
7. **Metrics curation** — `metrics:` config section; `setup`/`init-jobs` create only
   curated jobs; `curate-jobs` applies to an existing DB; `disable_uncurated` bulk-disables
   the rest (never deletes).
8. **`quickstart`** — config + setup + run in one command; refuses plaintext passwords in
   YAML (password file 0600 or NETCONF_PASSWORD).
9. **Log hygiene** — ncclient/paramiko silenced to WARNING unless `--verbose`;
   `setup_report.json` now per-device (next to config) with legacy fallback.
10. **Idle-transaction fix** — `run` held an idle-in-transaction PG session for its whole
    lifetime (all 3 bridges showed it; doctor flags it); startup session now committed
    before serve.

## Fixes (file — what)
Security:
- netconf/client.py `_is_auth_error` — broadened beyond "authentication failed" to access-denied/
  session-limit/lock-denied/too-many-sessions signatures. ALWAYS-ON; these were being retried like
  transient blips, risking the exact device lockout the breaker exists to prevent.
- trigger_api.py — bearer token compared with hmac.compare_digest (was `!=`, timing side channel).
- netconf/setter.py — element/predicate-key NAMES validated as XML QNames (values were already
  escaped; names were interpolated into tags raw → edit-config/XML injection via crafted Set path).
- mcp_server.py — set policy now evaluated fail-closed across ALL path forms the write could resolve
  to (raw, predicate-stripped, alias-resolved); previously checked one canonicalization while
  device.set applied another → policy bypass.

gNMI server / paths:
- gnmi_server.py serve() — raises on add_insecure_port()==0 (grpc's silent bind-failure sentinel);
  was starting a non-listening server while CLI printed "ready".
- gnmi_server.py — heartbeat anchored to now (last_hb=0.0 fired an immediate empty heartbeat).
- pathing.is_path_prefix — boundary-aware on '/' AND '[' ; cli LiveCache.match_prefix switched from
  loose startswith to is_path_prefix. Converges API and CLI stacks (were divergent) AND fixes
  '/system' matching '/system-backup' while keeping '/pm/otnpm-data' matching keyed PM paths.
  Verified live: /pm/otnpm-data still returns 21 keyed values post-fix.
- gnmi_server._parse_predicates — skips empty key names ('[=v]').

NETCONF resilience:
- client.get_server_capabilities — releases the pool lock during the reconnect sleep (it held the
  lock across sleep + network I/O, unlike _call_rpc which was written to avoid exactly this).
- client._force_close_session — runs the SSH close in a daemon thread with a join deadline; a wedged
  transport could block close() while the pool lock is held, freezing the whole pool.
- client.get_status — lock-free (was acquiring the lock held across NETCONF RPCs, so /health blocked
  behind any in-flight poll for up to rpc_timeout).
- yang_fetcher — removes the just-written .yang file if the DB insert fails, so retry is deterministic.

DB / planner / catalog:
- db/session.make_engine — pool_pre_ping=True + pool_recycle=1800. Classic multi-day-server fix:
  a connection killed after idle now gets transparently replaced instead of erroring on next query.
- planner.plan_batched_queries / plan_module_batched_queries — dedupe to ONE task per target at the
  MIN interval. Keying by (target, interval) emitted duplicate subtree polls when batched siblings
  had different intervals — and the new per-pattern metric intervals make that common.
- catalog.build_pyang_context — surfaces pyang load/validate errors (warns which YANG files failed)
  instead of silently dropping a module's paths from the catalog ("covered but isn't").

- normalize_path mangling colons in key values: apply_list_keys + _path_to_str percent-encode values

- alias uniqueness IntegrityError: ensure_unique_aliases dedups before upsert; not a reachable path.
- _typed_value bool-as-int: bool is already checked before int.

# Round 7: cross-interface live smoke tests (sim://openroadm) + 3 bugs they caught

Added tests/test_interface_parity_sim.py — drives ALL FOUR interfaces against the
simulator and asserts a known value (node-id=ROADM-SIM-01) actually comes back. The
static feature-parity matrix only checks method/tool/command EXISTENCE; these catch
runtime breakage. Building them surfaced 3 real bugs:

1. **TUI telemetry never matched keyed paths** (fixed earlier this session, Round 6 follow-up):
   the TUI kept its own _path_to_str that rendered list-key values DECODED while the bridge
   serves them percent-ENCODED → watched keyed path never matched the Get response. Fixed by
   reusing the gNMI server's canonical helpers + encoding-tolerant _paths_match. (Found by
   manually driving the real TUI against teraflex.)
2. **API-stack gNMI server returned nothing for aliased queries** (cache_store.py): MemoryCache.
   match_prefix compared RAW paths, but _LiveCacheView resolves the query through the alias map
   to the PREFIXED canonical form while the cache stores UNPREFIXED (namespace-stripped) paths →
   never matched. The CLI stack's CacheView normalizes both sides; MemoryCache didn't. Fixed:
   normalize both sides in MemoryCache.match_prefix. This made the API/CLI-simulate gNMI server
   actually serve aliased paths.
3. **`splice --simulate <profile> run` always failed** (api/device.py): _cmd_simulate_run
   constructs Device("sim://placeholder", simulate=profile), but Device.__init__ let the sim://
   host scheme OVERRIDE the explicit simulate= kwarg → always tried profile "placeholder" →
   ValueError. Fixed: explicit simulate= kwarg now wins (host scheme is a fallback). Verified the
   CLI sim run now binds and serves.

Smoke coverage per interface (all assert a real value flows through):
- Python API: Device("sim://openroadm").get(...) + find_paths.
- MCP: connect_device -> get_telemetry -> list_capabilities tools.
- CLI/gNMI server: Device.serve() in-process Get + the real CLI subprocess (--simulate ... run)
  with trigger-extension on-demand read.
- TUI: TelemetryService against a served sim port (the exact code the matching bug lived in),
